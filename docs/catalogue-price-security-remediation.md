# Catalogue Price Security Remediation — post-Gate D

Tracking: #39. This is an **infrastructure-only draft**: no vehicle prices, user data, photos, finance, offline scripts, scheduled refreshes or PhotoHarvest PR #38 are changed.

## Strict trust boundary

- PRs that touch `data/catalogue.json`, `js/catalogue-data.js` or `docs/catalogue-publication-evidence/approval-bundle.json` must change exactly those three paths together. CI checks the diff against the pinned PR base SHA and compares **exact generated bytes** from the trusted base catalogue and identity.
- For these PRs the checked-in `docs/catalogue-publication-evidence/approval-bundle.json` contains version 1, `research`, `researchAuthorisation`, `reviews`, and `authorisation`. Reviewers must independently inspect sources and the full payload; CI verifies signatures, not truth of claims.
- Research and review use **separate Ed25519 signing keys** registered as enabled researchers and approvers in `config/catalogue-publication-approvers.json` (schema version 2). Research identity, complete offer list, base catalogue, identity and research contents are signed by the researcher. The reviewer signs the research-authorisation digest, review manifest and explicit status-promotion allowlist, binding all reviewed evidence.
- Real trust registries remain **empty**. Onboard independently verified public keys via a separately reviewed PR; never add private keys. Until then any price-changing PR fails closed. Do not bypass the guard via workflow edits or a changed trust registry in the same publication PR.
- Production CLI no longer accepts `--as-of`; source freshness is checked against today's UTC date. Tests still inject a fixed date via the pure function, strictly for deterministic fixtures.
- Gate D still generates files only into a fresh temp directory with `--emit`. The PR guard merely validates the protected-branch diff and never publishes.
- GitHub main ruleset must be updated separately by the administrator: require at least one independent approving review; ideally require CODEOWNERS for the catalogue outputs, approval registry and workflows. The existing ruleset does not currently require a review.
- This guard runs within `verify`, which main branch protection already requires. Before merging the hardening PR verify the guard itself cannot be bypassed via a PR-modified workflow and that branch protection references the expected check. Configure stricter review requirements before trusting any real price release.
- Note: this control is for **pull requests**, not direct-push detection. Branch protections and permission controls must prevent unauthorised pushes or bypasses.
